# DVC Dataset Versioning and Rollback Evidence

## Scope

This report records the approved curation rule for the raw HARD review dataset:
exclude every source row whose normalized review text is associated with more
than one mapped sentiment label. Normalization uses the project
`clean_review_text` function (string conversion, trim, and whitespace collapse),
and sentiment mapping uses `RATING_TO_SENTIMENT` from the existing
preprocessing module. No labels or review text were invented.

Version 1 remains unchanged in the DVC remote and in Git history. Its original
bytes were copied to `/tmp/arabic-sentiment-v1-8b3523338727a05a3f8bac9522073b75.txt`
and verified before the working raw-data path was changed.

## Curation result

| Quantity | Observed value |

| Version 1 source rows | 105,698 |

| Version 2 rows | 105,657 |
| Version 2 negative rows | 52,841 |
| Version 2 positive rows | 52,816 |
| Conflicting groups remaining under the same normalization/mapping | 0 |

The curated dataset was generated by:

```bash
PYTHONPATH=src .venv/bin/python scripts/curate_conflicting_reviews.py \
  data/raw/balanced-reviews.txt /tmp/arabic-sentiment-v2-balanced-reviews.txt
```

The helper reads the existing UTF-16 tab-separated source, derives conflict
groups using the existing preprocessing functions, filters every row whose
normalized review matches a conflict group, and preserves columns and row
order. A dataframe equality check confirmed that Version 2 is exactly Version
1 filtered by that rule.

## Pipeline reproduction

Both isolated versions completed the existing `prepare → train → evaluate`
pipeline without changing its parameters or model type. The lightweight
TF-IDF/logistic-regression model is only the DVC reproducibility demonstration;
the official AraBERT artifact was not touched.

The earlier isolated runs exposed two issues: the first Version 1 attempt used
system Python and exited 1 because pandas was unavailable; a project-interpreter
retry reached evaluation but exited 255 because the Git-tracked snapshot was
also the DVC stage output. A temporary-index workaround enabled those initial
isolated validations. The ownership fix below removes the need for that
workaround in the primary checkout.

The successful normal primary-checkout command was:

```bash
PATH=/home/mah/projects/arabic-sentiment-mlops/.venv/bin:$PATH \
PYTHONPATH=src TMPDIR=/tmp/dvc-repro-primary \
/home/mah/projects/arabic-sentiment-mlops/.venv/bin/dvc repro
```

It exited 0 and ran Version 2 prepare (105,657 rows), train (84,525 rows), and
evaluation, then updated `dvc.lock`. The generated metric was copied to the
tracked CI candidate snapshot. Its test macro-F1 is `0.9385747787247837`, below
the unchanged baseline `0.9392593984962405`, so the quality gate correctly
exits 1.

After the ownership fix, Version 1 was also reproduced in the isolated
`/tmp/arabic-v1-fixed-check` checkout using the project Python environment,
the current pipeline definitions, and the Version 1 pointer from
`8f976ca…`. `dvc pull` retrieved Version 1 and its MD5/SHA-256 were verified;
normal `dvc repro` exited 0 without Git-index manipulation, producing prepare
and training inputs of 105,698 and 84,558 rows. The temporary checkout was
removed after verification. Its current evaluator emitted test macro-F1
`0.9392593984962405`, matching the preserved Version 1 quality-gate baseline.
The earlier isolated run details and its evaluator-schema limitation are
retained in the table below.

`dvc metrics show` reported generated Version 2 test accuracy `0.93858`, F1
`0.93891`, and macro-F1 `0.93857`; validation accuracy was `0.93716`, F1
`0.93745`, and macro-F1 `0.93716`. `dvc metrics diff` showed no `HEAD` metric

## Rollback scope and limits

The Git/DVC checkout-and-rollback requirement is complete for the two recorded
dataset versions. The host-side test retrieved Version 1, retrieved Version 2,
then checked out Version 1 and retrieved it again; the expected MD5 was
verified at each step. Pipeline reproduction results are recorded separately
above. Dataset rollback does not demonstrate MLflow model-registry rollback or
production-service rollback.

The DVC pointer and both dataset content hashes are versioned in Git/DVC; the
dataset bytes remain outside Git.
